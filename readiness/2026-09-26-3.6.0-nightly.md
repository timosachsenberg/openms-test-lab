# Release readiness: OpenMS 3.6.0, nightly 2026-09-26 (checked 2026-09-26)

**Verdict: NOT READY**

This nightly is incomplete. The pyOpenMS wheels `3.6.0.dev20260926` come from `3e73c70`, which is
develop after OpenMS/OpenMS#10277. The Release run on the same revision
([36208609362](https://github.com/OpenMS/OpenMS/actions/runs/36208609362)) failed in its macOS
notarization step, when the runner lost its network connection. As a result, no installer of this
nightly was deployed, for any platform, and `nightly/2026.09.25` is still the newest installer folder.

The OpenSSL pin (OpenMS/OpenMS#10269) is not in this revision, so the lab matrix and the OpenSSL
checks were not rerun. The rules for the other checks:
- Checks that need the installers carry over from the
  [2026-09-25 report](2026-09-25-3.6.0-nightly.md), marked as carried over.
- These checks were rerun on this revision: A1–A3 for the wheels, D1, D2, D6, and the source audit
  behind E1–E8.

What changed:
- E1, E2 and E3 now pass (OpenMS/OpenMS#10277).
- D1 is down from 25 unannounced names to 19. OpenMS/OpenMS#10272 announces the rest. It was
  merged into develop at 06:04 UTC, after this nightly was built.

## Blocking failures

1. **A1, A2 — this nightly has no installers.** The Release run built and packaged all four
   platforms. Then the macOS job's `Notarize macOS Package` step failed: `notarytool` had uploaded
   the `.pkg` (submission `b2554f12-…`), but while it waited for the result the runner reported
   `NSURLErrorDomain Code=-1009 "The Internet connection appears to be offline" … No network route`
   ([job log](https://github.com/OpenMS/OpenMS/actions/runs/36208609362/job/108310344387)). The failure
   is in the runner's network, not in the code, but it matters for the release:
   - one failed notarization skips the deployment of every platform's installer;
   - `notarytool` could resume by submission ID (`xcrun notarytool wait <id>`) instead of failing
     the job.
   A rerun of the failed job would publish this nightly's installers.
2. **D2, D5 — the pyOpenMS user guide is broken by 3.6.0.** See D2 and D5 below.
   - OpenMS/OpenMS#10272 (merged) fixes the default-argument regressions and adds the BREAKING notes.
   - OpenMS/OpenMS#10280 (open) fixes `plot_spectrum` and `get_df(long=True)`.
3. **D1 — removed Python API is not announced.** 19 of the 36 removed names are not in the
   CHANGELOG of `3e73c70`. With the CHANGELOG of develop at `fd4fb07` (#10272) the count is 0.
4. **F6 — OpenSSL 3.0.8 in the DEBs and the `.pkg`.** Carried over. `vcpkg.json:59` of `3e73c70`
   still pins `openssl` 3.0.8; OpenMS/OpenMS#10269 raises it and waits on review.
5. **F7 — the Windows installer is not signed.** Carried over; `release.yml` did not change
   between `8b25c6e` and `3e73c70`.
6. **C3 (macOS) — `ExecutePipeline` cannot find the Qt platform plugin.** Carried over; fix in
   OpenMS/OpenMS#10280.
7. **C5 — the vendor readers work only on the non-default path.** Carried over; fixes in
   OpenMS/OpenMS#10273 and #10274.
8. **E8 — the CHANGELOG is not clean.** One duplicated bullet and two orphaned lines at `3e73c70`;
   OpenMS/OpenMS#10267 removes them.
9. **E4 — headline features lack user documentation.** Carried over.
10. **F1 — macOS 14 is claimed, macOS 15 is needed.** `CHANGELOG:195` of `3e73c70` still says
    "minimum macOS version is 14"; the new macOS wheel is again tagged `macosx_15_0_arm64`.
