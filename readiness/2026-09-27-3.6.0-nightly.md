## Blocking failures

1. **C5: the default Thermo reader fails on Linux and macOS.**
   - `FileConverter -in ginkgotoxin-ms-switching.raw -out x.mzML` exits 14, because
     `ThermoRawFileParser.exe` is not on the PATH. This happens on Linux x64 (R, B6),
     Linux arm64 (B7) and macOS (B3).
   - The in-process reader writes all 32 spectra on every platform.
   - On Windows, all three readers write 32 spectra (B1).
   - OpenMS/OpenMS#10274 makes the in-process reader the default on Linux and macOS. It was merged
     after this nightly was built, so the 2026-09-28 nightly is the first that can pass.
2. **D5: the `char` change has no migration note.**
   - `char` arguments now take a one-character `str` and reject `bytes`; for example,
     `PeptideEvidence.setAABefore(b"R")` raises `TypeError`.
   - The CHANGELOG even says "string arguments also accept bytes" (`CHANGELOG:256`).
   - The user guide already uses `"R"` (OpenMS/OpenMS#10285).
   - OpenMS/OpenMS#10289 adds the BREAKING entry, with the affected methods.
3. **E4: headline features without user documentation.** Carried over; no user documentation for
   these features changed.
4. **F7: the Windows installer is not signed.** `osslsigncode verify` finds no signature, and
   `release.yml` has no signing step. Resolving this needs a maintainer's decision: a code-signing
   certificate, or a written waiver for 3.6.0.
5. **F8: third-party licenses do not ship with what they cover.** `share/OpenMS/LICENSES/` holds only
   the OpenMS license, as before.

Not blocking by the definition of D2, but still broken on this candidate: three user-guide pages
fail. `map_alignment.rst:154` and `peptide_search.rst:225` need calls that OpenMS/OpenMS#10289
restores. `export_pandas_dataframe.rst:250` needs OpenMS/OpenMS#10288. See D2.

## Other findings

- **The `.pkg` enforces no minimum macOS.**
  - Its Distribution file has no `allowed-os-versions`, and the apps' `LSMinimumSystemVersion` is 12.0.
  - It needs 15.0: `libOpenMS` reaches the bundled `libzstd` (minos 15.0) through Arrow and Boost.
  - OpenMS/OpenMS#10286 declares 15 in the build target, the installer and the apps' `Info.plist`.
- **The D2 check misses rewritten pages.** It counts a failing page only if it ran with the previous release. After the user guide was rewritten for 3.6, all three broken pages fail on `3.5.0` too, so they no longer count. Consider also failing on any page that fails with the candidate and needs no optional package.
- **mypy rejects five names that the stubs import without re-exporting.**
  - `PeakMap`, `PeakSpectrum`, `Kernel_MassTrace`, `TM_DataPoint` and `MZTrafoModel_MODELTYPE` fail with "does not explicitly export".
  - The 2026-09-25 wheel has the same problem. Advisory, next to F4.
- **`dist-info/LICENSE` of the wheels contains only the string `BSD-3-Clause`,** in all four wheels, as on 2026-09-25. The actual license text ships as `LICENSES/OpenMS-BSD-3-Clause.txt`.
- **`SageAdapter` leaves files behind:** its configuration JSON in the temporary directory and `results.sage.*` in the working directory.
- Reproduce any of this with the commands in [RELEASE-READINESS.md](../RELEASE-READINESS.md).
