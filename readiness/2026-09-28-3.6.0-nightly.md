# Release readiness: OpenMS 3.6.0, nightly 2026-09-28 (checked 2026-09-28)

**Verdict: NOT READY**

This nightly has four wheels and four installers, all built from `8adb3b1`: develop after
OpenMS/OpenMS#10258, the last merge of 2026-09-27. It is the first nightly with the in-process
Thermo reader as the default on Linux and macOS (OpenMS/OpenMS#10274) and with the pyOpenMS fixes
OpenMS/OpenMS#10288 and #10289. The checks show:
- **Fixed in this nightly:**
  - C5: the default Thermo reader writes all 32 spectra on every platform, and all eight lab
    runs are green;
  - D2 and D3: all 39 runnable user-guide pages pass, without a deprecation warning;
  - D5: the `char` arguments have their BREAKING note;
  - F1: the `.pkg` refuses macOS older than 15, and its apps declare 15 (OpenMS/OpenMS#10286).
- **F7 passes because the rule changed**, not the installers: a maintainer signs the Windows
  installer by hand before it is published (decision of 2026-09-27), and G10 checks that copy.
- **Still blocking:**
  - E4: at this revision the headline features have no user documentation. The documentation
    PRs were merged on 2026-09-28, after this nightly was built.
  - F8: third-party licenses.
- **The lab missed a new upstream test**, `TOPP_FileConverter_RAW_default_reader`. Lab
  `f7a54a9` fixes the detection, and the reruns pass the test on every platform (C3).

## Blocking failures

1. **E4: the headline features have no user documentation at this revision.**
   - Between `f0f2424` and `8adb3b1` only two user-facing texts changed: `export_pandas_dataframe.rst`
     (OpenMS/OpenMS#10288) and FileConverter's tool page, for the new reader default
     (OpenMS/OpenMS#10274). The gaps of 2026-09-27 remain.

     They were merged on 2026-09-28 after this nightly was built, so the 2026-09-29 nightly is
     the first that can pass.
2. **F8: third-party licenses do not ship with what they cover.**
   - `share/OpenMS/LICENSES/` still holds only the OpenMS license.
   - OpenMS/OpenMS#10292 (open, green) adds the texts for the vcpkg ports, Qt, the macOS Homebrew
     libraries and the code vendored in the source tree.
   - The rest needs work beyond that PR:
     - the Thermo RawFileReader license for the bridge (OpenMS/OpenMS#10259, open);
     - license files for Comet, MaRaCluster, Percolator and X!Tandem in OpenMS/THIRDPARTY, and
       the removal of SpectraST;
     - Windows `THIRDPARTY/pwiz-bin`;
     - the .NET assemblies bundled with ThermoRawFileParser;
     - the contrib libraries in the wheels.

## Other findings

- **The C3 replay missed a new upstream test.**
  - OpenMS/OpenMS#10274 added `TOPP_FileConverter_RAW_default_reader` under `if(WITH_THERMO_RAW)`.
  - The replay did not define that build option, so R and the first lab runs reported the test as not registered on every platform.
  - Lab `f7a54a9` reads the option from FileConverter's INI: `RawToMzML:reader` accepts `inprocess` only in builds `WITH_THERMO_RAW`.
  - Against the 2026-09-27 DEB, the test now fails, because that nightly still defaulted to the external reader. So the replay would have caught the 2026-09-27 C5 failure as well.
  - Against this nightly it passes on all four platforms.
- **Two nightlies share file names and version.**
  - The installers of 2026-09-27 and 2026-09-28 have the same names and both report `3.6.0-pre-nightly-2026-09-27`.
  - The reason: `CMakeLists.txt` names a nightly after the date of its newest commit, and `8adb3b1` was committed on 2026-09-27 at 20:11 +02:00.
  - Only the folder, the sha256 and `Revision:` tell the two apart. The wheels carry `dev20260928`.
- **FileConverter and pyOpenMS return different peak types for Thermo files by default.**
  - FileConverter centroids: 11,813 peaks.
  - `ThermoRawFile().load` keeps the profile scans (174,162 peaks) unless `ThermoRawFileOptions.centroid` is set, as `ThermoRawFile.h` documents ("Preserve acquired representation by default").
  - `FileHandler`, and with it the other tools that read `.raw`, centroids too from OpenMS/OpenMS#10303 on, which is not in this nightly.
- **On Linux and macOS, only the in-process Thermo reader was exercised.**
  - The default and `-RawToMzML:reader inprocess` are the same reader there now.
  - `-RawToMzML:reader external` exits 14, because these packages ship neither ThermoRawFileParser nor mono.
  - The external reader ran on Windows only, with 32 spectra.
- **mypy rejects five names that the stubs import without re-exporting**: `PeakMap`, `PeakSpectrum`, `Kernel_MassTrace`, `TM_DataPoint` and `MZTrafoModel_MODELTYPE`, "does not explicitly export". Unchanged; advisory, next to F4.
- **`dist-info/LICENSE` of the wheels contains only the string `BSD-3-Clause`,** in all four wheels, as before. The license text ships as `pyopenms/share/OpenMS/LICENSES/OpenMS-BSD-3-Clause.txt`.
- **`SageAdapter` leaves files behind:** its configuration JSON in the temporary directory, and `results.sage.*`, `results.json` and `matched_fragments.sage.tsv` in the working directory. Unchanged.
- Reproduce any of this with the commands in [RELEASE-READINESS.md](../RELEASE-READINESS.md).
