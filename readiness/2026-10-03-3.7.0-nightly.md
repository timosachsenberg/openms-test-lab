# Release readiness: OpenMS 3.7.0, nightly 2026-10-01 (checked 2026-10-03)

**Verdict: NOT READY**

This is the first check after the 3.6.0 release, so the baseline is now `3.6.0` (tag `v3.6.0`).
The newest nightly with a complete artifact set is `e25ac614`, which is develop on the morning of
2026-10-01: four wheels `3.7.0.dev20261001` and four installers in `nightly/2026.10.01`.

There are newer wheels, from 2026-10-02 (`c4d2b6b`) and 2026-10-03 (`f6c680f`), but no installers
for them. Both Release runs failed because Apple's notary service refused to accept the submission
(HTTP 403, "A required agreement is missing or has expired"). The newest wheel was checked in
addition, for the wheel-only checks (D, E).

The candidate is in much better shape than the 3.6 nightlies:
- Every tool starts and every upstream TOPP test passes on all four platforms.
- The default Thermo reader works everywhere, and the adapters find their bundled engines.
- The DEB upgrades cleanly from 3.6.0.
- The pyOpenMS API has not changed since 3.6.0, and no user-guide page regressed.

Four blocking checks fail on this revision:
- F6: OpenSSL 3.6.4 has a new High advisory.
- F7: the unsigned Windows installer, unchanged.
- F8: license gaps, now down to four libraries.
- F11: the relocatable macOS apps. Develop has the fix, but no installer with the fix is published.

Develop adds two more blocking findings for the next candidate:
- A1: the notarization agreement, which stops every installer.
- E2: OpenDIA is missing from *New tools*.

## Blocking failures

1. **F6: every artifact bundles OpenSSL 3.6.4, which has a High advisory.**
   - [CVE-2026-84782](https://nvd.nist.gov/vuln/detail/CVE-2026-84782) (NVD 8.2, DTLS only) is fixed in 3.6.5.
   - Where 3.6.4 ships:
     - both DEBs and the `.pkg` ship `libcrypto` 3.6.4 (R, B6, B7, B3);
     - the Linux wheels name it in `libOpenMS`, and the macOS wheel ships `libcrypto.3.dylib` 3.6.4;
     - the Windows installer and wheel link it statically into `OpenMS.dll`, where `bundled-libs.py` cannot see it (*Other findings*).
   - Develop still pins it (`vcpkg.json:60`, `"openssl", "version": "3.6.4"`), and no open PR changes that.
   - 3.6.0 shipped it as a documented known issue (CHANGELOG, OpenMS/OpenMS#10348). That acceptance covers 3.6.0, not 3.7.0.
   - The bundled engines still carry the copies that 3.6.0 lists as known issues:
     - Comet's zlib 1.2.11 ([CVE-2022-37434](https://nvd.nist.gov/vuln/detail/CVE-2022-37434), Critical 9.8; [CVE-2018-25032](https://nvd.nist.gov/vuln/detail/CVE-2018-25032), High 7.5);
     - MaRaCluster's zlib 1.2.3 (CVE-2018-25032);
     - Sage's SQLite 3.41.2, built with FTS5 ([CVE-2025-6965](https://nvd.nist.gov/vuln/detail/CVE-2025-6965), High 7.7; [CVE-2026-11822](https://nvd.nist.gov/vuln/detail/CVE-2026-11822), High 7.8).
   - Fix: pin OpenSSL 3.6.5 or newer, and rebuild the engines, as the 3.6.0 CHANGELOG plans.
2. **F7: the Windows installer is not signed.** `osslsigncode verify` finds no signature. This needs a maintainer's decision: a code-signing certificate, or a written waiver.
3. **F8: four bundled libraries ship without their license.** Since 3.6.0, `share/OpenMS/LICENSES/`
   holds the vcpkg, vendored, Qt and Homebrew licenses, and every engine folder has its own. What is left:
   - The DEB bundles `libgfortran.so.5` (GPL-3.0 with the GCC Runtime Library Exception) without its license. The wheels ship it, under `LICENSES/system/libgfortran/`.
   - The `.pkg` bundles glib (`libglib-2.0`, `libgthread-2.0`; LGPL-2.1+), harfbuzz (MIT) and pcre2 (BSD) without their licenses. `LICENSES/homebrew/` has 26 formulae, not these three.

   The 3.6.0 DEB and `.pkg` have the same gaps.
4. **F11: the `.pkg` lets the Installer relocate TOPPView, TOPPAS and INIFileEditor** (R, run 10).
   - OpenMS/OpenMS#8479 and #10385 fix this. Both were merged after `e25ac614`.
   - The CPack probe of run 10 packages stub apps with the scripts of `f6c680f`: the Applications component lists no relocatable bundle, and `BundleIsRelocatable` is false.
   - The first installer built after the notarization agreement is renewed should pass.

**Also blocking, for the next candidate.** These come from develop and are not part of `e25ac614`:

5. **A1: no installer has been published since 2026-10-01.**
   - The Release runs [36951917668](https://github.com/OpenMS/OpenMS/actions/runs/36951917668) (2026-10-02) and [37086605095](https://github.com/OpenMS/OpenMS/actions/runs/37086605095) (2026-10-03) fail in *Notarize macOS Package*.

   - *Deploy Installer* needs all four build jobs, so the green Linux and Windows packages of those runs were not deployed either.
   - Fix: the account holder of team `C64UCGJ5PL` has to accept the current agreement in the Apple Developer account. Retrying cannot help.
6. **E2: OpenDIA is new in 3.7.0, but the CHANGELOG does not list it under *New tools*.**

   - The 3.7.0 section mentions it only as a changed tool (OpenMS/OpenMS#10404).
