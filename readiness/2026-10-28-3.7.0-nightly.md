# Release readiness: OpenMS 3.7.0, nightly 2026-10-28 (checked 2026-10-28)

**Verdict: NOT READY**

This report covers the nightly of 2026-10-28, built from `65cbd79fc1` (develop on 2026-10-27).
The automated gate (Nightly readiness) ran on all four platforms, plus the container image on
x64 and arm64. Every blocking check it decides passes except E2. The checks done by hand add
two more blocking failures. Blocking failures:

- **E2:** the new tool `EntrapmentEvaluator` (OpenMS/OpenMS#10629) is not in the CHANGELOG.
- **F7:** the Windows installer is not signed, as in every 3.6.0 nightly.
- **F8:** the PeptDeep ONNX models (Apache-2.0) ship without their license.

E4 cannot be decided on a nightly, because the release's headline list (*General*, *PyOpenMS*)
is written at release prep.

The scheduled gate on the lab's `main` failed for this nightly with 11 blocking failures (run
40680355685). Ten of them were the lab's own: the C3 replay, and D1's matching of class names
in the CHANGELOG. Both are fixed on the lab branch `claude/openms-test-release-readiness-ks3twg`.
The verdict below comes from that branch.

## Blocking failures

1. **E2: `EntrapmentEvaluator` is not in the CHANGELOG.**
   - OpenMS/OpenMS#10629 added the tool, `DecoyDatabase -entrapment_ratio`/`-entrapment_string`
     and the library class `EntrapmentEvaluation`, but no CHANGELOG entry for any of them.
   - Evidence: R `docs-audit.json`, `DOC-TOOL-CHANGELOG`.
   - The fix is [OpenMS/OpenMS#10766](https://github.com/OpenMS/OpenMS/pull/10766), merged into develop on
     2026-10-28 as `dec18943e0`, after this nightly was built; the next nightly has to show E2 green. It has all three
     entries. With it, the audit reports nothing missing. The last CHANGELOG sync (#10695) predates
     #10629, and the weekly sync workflow is disabled.
2. **F7: the Windows installer is not signed.**
   - `osslsigncode verify` on the `.exe` finds no signature.
   - The `.pkg` passes: signed *Developer ID Installer: OpenMS Inc. (C64UCGJ5PL)*, notarized
     (status *Accepted*), ticket stapled, and `spctl` accepts it ([macOS job of Release run
     40614232656](https://github.com/OpenMS/OpenMS/actions/runs/40614232656/job/122572852347)).
   - Unchanged since the 3.6.0 nightlies; `release.yml` has no Windows signing step.
3. **F8: the PeptDeep models ship without their license.**
   - `share/OpenMS/models/peptdeep_{ccs,ms2,rt}_dynamic.onnx` are in the DEB. The Container
     image labels them Apache-2.0 (AlphaPeptDeep).
   - No license or NOTICE file for them is installed: `src/openms/CMakeLists.txt` downloads the
     models from archive.openms.de and installs only the `.onnx` files. Apache-2.0 §4(a) requires
     a copy of the license with the work.
   - Everything else is covered: every engine under `THIRDPARTY/` has its license, every library
     in `/usr/lib` has a license under `LICENSES/vcpkg/` (ONNX Runtime included), and there are
     `LICENSES/system/` and the Thermo license. This is new with the ONNX models in the packages.

Blocking but not decided (not run):
- **E4:** the release's headline list does not exist yet. See E4 below.
- **E9:** its Doxygen part. The Sphinx part passes. See E9 below.

## Other findings

- **The lab, not OpenMS, failed the scheduled gate.** The gate on the lab's `main` has failed every
  nightly since 2026-10-22. The C3 failures there are replay gaps:
  - `WITH_ONNX` was not detected, so `TOPP_OpenDIA_predicted_requires_onnx` ran on packages with ONNX;
  - tests ran before tests defined later in the files that they `DEPENDS` on;
  - `foreach(… IN ZIP_LISTS …)`, `string(MAKE_C_IDENTIFIER)` and `list(REMOVE_AT)` were not replayed;
  - `PASS_REGULAR_EXPRESSION` was matched without letting `.` span lines, as CTest does;
  - fixtures were ignored.
  The D1 failure was the full-name matching. All of this is fixed on the lab branch (`632ebf7`,
  `931d7fb`), which also adds C6, C9, C10 and E11 to the gate (`51b6fcc`). Until the branch is
  merged, the scheduled gate keeps reporting them.
- **F6 by hand:**
  - Bundled engines carry old static libraries: zlib 1.2.11 (Comet) and zlib 1.2.3 (MaRaCluster,
    x86_64 and macOS) predate the fixes for CVE-2018-25032 (High) and CVE-2022-37434 (Critical,
    through `inflateGetHeader` only).
  - Sage carries SQLite 3.41.2 (all platforms), before the fix for CVE-2023-7104 (session
    extension).
  - The Windows installer ships Qt 6.8.3; its advisories were not reviewed.
  - The macOS pkg ships OpenSSL 4.1.0 (Homebrew `openssl@4`) next to 3.6.5.
  - A person should confirm that the engines never reach the affected functions, or the engines
    should be updated.
