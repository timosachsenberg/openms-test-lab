# Release readiness: OpenMS 3.6.0, nightly of 2026-09-24 (checked 2026-09-25)

**Verdict: NOT READY**

The second run of [RELEASE-READINESS.md](../RELEASE-READINESS.md), against the nightly published on
2026-09-25. Unlike the [previous report](2026-09-24-3.6.0-nightly.md), every artifact now comes
from one revision, `8b25c6e`, and the whole release matrix ran, including the four runs that were
skipped last time (B2, B5, B8, B9). All eight labs install and run pyOpenMS, and all four desktop
packages install. On Windows, Linux x64 and Linux arm64, every registered upstream TOPP and TOPPAS
test passes against the installation. What changed since the previous report:

- Fixed: A2 (one revision), D6 (the wheel workflow is green for this revision), and the nightly
  Bioconda deploy, which is green again.
- Run for the first time: B2, B5, B8 and B9 (all pass), E9 (passes, including Doxygen), and F2–F5
  (F2 and F5 pass; F3 and F4 have advisory failures).
- New failure: F7. The Windows installer is not signed, and `release.yml` has no step that could
  sign it.
- Unchanged: the blocking failures in pyOpenMS (D1, D2, D5), the bundled OpenSSL (F6), the macOS
  TOPPAS pipelines (C3), the vendor readers (C5), the documentation (E1, E2, E4) and the platform
  claims (F1, C6).

Only four OpenMS commits separate this nightly from the previous report's installers
(OpenMS/OpenMS#10262, OpenMS/OpenMS#10257, OpenMS/OpenMS#10245, OpenMS/OpenMS#10255). None of them
touches the code or the documentation behind these findings. OpenMS/OpenMS#10255 makes the WNet
alignment opt-in, so the packages no longer ship FeatureLinkerWNet.

## Blocking failures

1. **D2, D5 — the pyOpenMS user guide is broken by 3.6.0.** The same 15 pages as in the previous
   report fail with the nightly and run with 3.5.0 (18 pass, 21 fail in total). The causes are
   unchanged (table under D5). Four of them are bugs in the package:
   - `pyopenms.plotting.plot_spectrum` and `mirror_plot_spectrum` call `.decode()` on a `str`
     (`plotting.py:348`; `spectrum_alignment.rst:49`, and `ms_data.rst:204`, which fails with
     both versions).
   - `Residue.getMonoWeight()` (`peptides_proteins.rst:73`) and `MSDataCachedConsumer(filename)`
     (`reading_raw_ms_data.rst:247`) lost their default arguments.
   - The deprecated `get_df(long=True)` no longer accepts `long` (`export_pandas_dataframe.rst:65`).

   The rest are intentional API changes with no BREAKING note. OpenMS/OpenMS#10260 (label
   `blocker`) collects fixes for the plotting and `get_df` bugs and for failure 5; it has no pull
   request yet.
2. **D1 — removed Python API is not announced.** Unchanged: 36 public names are gone since 3.5.0,
   and 25 of them appear nowhere in the CHANGELOG (list under D1).
3. **F6 — the DEBs and the macOS package bundle OpenSSL 3.0.8.** Unchanged. `libcrypto` 3.0.8 in both
   DEBs and in the `.pkg` is affected by CVE-2026-45447 (High, fixed in 3.0.21) and CVE-2025-15467
   (High, fixed in 3.0.19). The version comes from the `"overrides": [{"name": "openssl", "version":
   "3.0.8"}]` pin in OpenMS `vcpkg.json`. The x86_64 Linux wheel bundles OpenSSL 3.5.8; the Windows
   installer bundles none. Evidence: `bundled-libs.json` of B3, B6, B7 and R.
4. **F7 — the Windows installer is not signed.** New in this report (it was not run before).
   `osslsigncode verify` on `OpenMS-3.6.0-pre-nightly-2026-09-24-Win64.exe` finds no Authenticode
   signature. `release.yml` at `8b25c6e` has no Windows signing step at all, so a tag build would not
   sign it either. The macOS package passes: it is signed with *Developer ID Installer: OpenMS Inc.
   (C64UCGJ5PL)* and notarized. The notarization status is *Accepted* and the ticket is stapled, and
   `spctl` reports *accepted* ([macOS job](https://github.com/OpenMS/OpenMS/actions/runs/36082352087/job/107906837183)).
5. **C3 (macOS) — `ExecutePipeline` cannot start, so TOPPAS pipelines cannot run from the command
   line.** Unchanged: the same 7 TOPPAS tests fail with `Could not find the Qt platform plugin
   "cocoa"`, and 2,157 other tests pass ([B3](https://github.com/timosachsenberg/openms-test-lab/actions/runs/36102930210)).
   The package has no `bin/qt.conf`. OpenMS/OpenMS#10260 proposes installing one.
6. **C5 — the vendor readers work only on the non-default path.** Unchanged, re-run on this DEB:
   - The default Thermo reader fails: `FileConverter -in x.raw` exits 14 because
     `ThermoRawFileParser.exe` cannot be found.
   - Bruker `.d.zip` input fails in `FileConverter` (exit 2, `opentims: Not a directory`) and in
     pyOpenMS `BrukerTimsFile().load`.
   - The native Thermo reader and unzipped `.d` directories work.
7. **E1, E2, E8 — CHANGELOG and tool pages.**
   - ParquetConverter is mentioned nowhere, and ParquetDiff is not under *New tools*. Its entry
     waits in the unmerged OpenMS/OpenMS#9873.
   - QuantmsIOConverter, the 3.5.0 name, is never mentioned.
   - SwathWizard and FLASHDeconvWizard were removed without an entry.
   - The page of the new TransitionListEvidenceFilter does not show its parameters.
   - The CHANGELOG still has a duplicated bullet and two orphaned fragments. OpenMS/OpenMS#10267
     (green, unmerged) removes all three. OpenMS/OpenMS#10252 overlaps with it.
8. **E4 — headline features lack user documentation.** Unchanged (table under E4).
9. **F1, C6 — the release claims more platforms than the packages support.** Unchanged:
   - The CHANGELOG says macOS 14. The wheel is tagged `macosx_15_0`, and 136 of its 137 Mach-O files
     need macOS 15.0.
   - The DEB needs `libc6 (>= 2.38)`. The Linux install page names no versions, links the 3.5.0 DEB
     on abibuilder and describes Qt5 on Xenial.

Release mechanics (G) were not exercised, because that needs a release-candidate tag.
`release.yml` is unchanged since the previous report, so its G notes still apply.
