# Release readiness: OpenMS 3.7.0, nightly 2026-10-07 (checked 2026-10-07)

**Verdict: NOT READY**

Nothing new can be qualified today. The newest published installers are still those of
`e25ac614` (`nightly/2026.10.01`), which the [2026-10-03 report](2026-10-03-3.7.0-nightly.md)
checked: NOT READY. Since then, every nightly built wheels (today `3.7.0.dev20261007`, from
`f9f81826`), but none published installers, so today's revision fails A1, and every check that
needs an installed package is *not run*.

The cause of the missing installers has moved on:
- Apple's notary service accepts the macOS package again since 2026-10-06.
- Since then, the macOS job fails one step later, in *Package the Developer SDK*: macOS's BSD
  `awk` rejects a newline in a `-v` value. OpenMS/OpenMS#10435 fixes that; it was merged at
  03:42 UTC today, after today's build had started. The 2026-10-08 nightly is the first that can
  publish installers again.

What could be checked today:
- **Today's wheels** pass the wheel labs on all four platforms and the automated wheel gate: the pyOpenMS API is unchanged since 3.6.0 (0 names removed or added), no user-guide page regressed, and the docs audit is clean apart from E2 and the advisory A3 and E1.
- **Today's installers** were built, though not published. I checked the artifacts of the Release run statically:
  - The notarized `.pkg` relocates no app bundle any more (F11 passes for the first time).
  - The DEB's Qt dependencies now install on Debian 13.
  - OpenSSL 3.6.4 (F6), the unsigned `.exe` (F7) and the missing licenses (F8) remain. F8 now also misses libpng in the `.pkg`.

## What changed since the 2026-10-03 report

- **Notarization works again.** The Release runs of 2026-10-04 ([37170311539](https://github.com/OpenMS/OpenMS/actions/runs/37170311539)) and 2026-10-05 ([37252610204](https://github.com/OpenMS/OpenMS/actions/runs/37252610204)) still got the 403. The runs of 2026-10-06 ([37400132080](https://github.com/OpenMS/OpenMS/actions/runs/37400132080)) and 2026-10-07 pass *Notarize macOS Package*.
- **A second blocker came out behind it.** `tools/ci/package_sdk.sh` (OpenMS/OpenMS#10248, on develop since 2026-10-02) fills the SDK README with `awk -v requirement="$boost_requirement"`, and that text has two lines:
  - macOS's BSD `awk` stops with `awk: newline in string No Boost: the OpenMS... at source line 1`, in the runs of 2026-10-06 and 2026-10-07.
  - The step comes after notarization, so the 403s hid it until 2026-10-06.
  - Reproduced on Linux with `original-awk`. `mawk` and GNU `awk` accept the newline, which is why only macOS fails.
  - OpenMS/OpenMS#10435 (`d63291dc`, merged 2026-10-07 03:42 UTC) passes the text through `ENVIRON`. Its exact invocation works with `original-awk`.
- **F11 is fixed in a real installer.** The notarized `.pkg` of today's run lists no relocatable bundle (`scripts/macos_pkg.py --expect-no-relocation`, exit 0).
- **The DEB installs on Debian 13** as far as its dependencies go: every Qt dependency now has the old name as an alternative (OpenMS/OpenMS#10367).
- **Unchanged on develop (`097bad20`):**
  - the OpenSSL 3.6.4 pin (`vcpkg.json:60`);
  - no Windows signing;
  - no *New tools* entry for OpenDIA;
  - the nightly documentation URL (`TOPPBase.cpp:731`).

## Blocking failures

1. **A1: no installer since 2026-10-01.**
   - Six nightly Release runs failed in a row: 2026-10-02 to 2026-10-05 at notarization (HTTP 403), and 2026-10-06 and 2026-10-07 at *Package the Developer SDK* on macOS.
   - *Deploy Installer* needs all four build jobs, so the green Linux and Windows packages were not published either.
   - The fix, OpenMS/OpenMS#10435, is merged. If tomorrow's run still fails, the next suspect is whatever follows the SDK step.
2. **F6: OpenSSL 3.6.4 (CVE-2026-84782, High).**
   - It is in the wheels (R: the x86_64 wheel links OpenSSL 3.6.4 statically into `libOpenMS`) and in today's DEB and `.pkg`. The pin is unchanged on develop, and no PR is open.
   - The engines' old zlib and SQLite copies are unchanged; see the 2026-10-03 report.
3. **F7: the Windows installer is unsigned.** `osslsigncode verify` on today's `.exe`: no signature.
4. **F8: licenses are missing.**
   - The DEB still bundles `libgfortran.so.5` without its license.
   - The `.pkg` still bundles glib, harfbuzz and pcre2 without theirs, and **`libpng16` lost its license**:
     - The 2026-10-01 `.pkg` had `LICENSES/homebrew/libpng/`; today's does not, while it still bundles `libpng16.16.dylib`.
     - The Homebrew licenses are collected from the runner's Homebrew kegs of Qt's dependencies. So the runner's Homebrew may have changed rather than OpenMS; I could not tell which.
   - The libraries new with ONNX (ONNX Runtime, protobuf, cpuinfo) are covered, in `LICENSES/vcpkg/`.
5. **E2: OpenDIA is not under *New tools*.** 
   - The docs audit of `f9f81826` (R) finds OpenDIA added since `v3.6.0` but not under *New tools*.
   - The 3.7.0 section mentions OpenDIA now, but only in FIX and performance entries.
   - OpenMS/OpenMS#10387, which adds an OpenDIA entry, has been open with a merge conflict since 2026-10-01.

Every blocking check that needs an installed package (B1, B3, B6, B7 with installers, C1–C3, C5, C6) is **not run** for today's revision; the verdict would be capped at NOT READY by that alone.
