# Release readiness: OpenMS 3.6.0, nightly of 2026-09-23 (checked 2026-09-24)

**Verdict: NOT READY**

The first run of [RELEASE-READINESS.md](../RELEASE-READINESS.md), against the newest nightly
wheels and installers. The desktop package is in good shape: on all four platforms the 154
registered tools start and the bundled engines start. Every upstream TOPP test that the
package's configuration registers passes against the installation, 2,162 to 2,185 per
platform. The TOPPAS pipeline tests pass on Linux and Windows. On macOS, `ExecutePipeline`
cannot start. The native Thermo reader works too. The release is blocked mainly by pyOpenMS:

- 15 pages of the pyOpenMS user guide that work with 3.5.0 fail with this nightly.
  Several of the causes are bugs in the package itself.
- Large Python API changes are neither announced in the CHANGELOG nor reflected in the user
  guide.
- The DEB and the macOS package bundle an OpenSSL affected by two High-severity advisories.
- On macOS, TOPPAS pipelines cannot run from the command line: `ExecutePipeline` finds no Qt
  platform plugin.
- Documentation gaps and the release mechanics are still open.

Linux arm64, macOS and Windows results come from the lab runs listed under B.

## Blocking failures

1. **D2, D5 — the pyOpenMS user guide is broken by 3.6.0.** 15 pages that run with 3.5.0 fail
   with the nightly (18 pass, 21 fail in total). Four of the causes are bugs in the package:
   - `pyopenms.plotting.plot_spectrum` and `mirror_plot_spectrum` crash on any annotated
     spectrum: `plotting.py:348` calls `.decode()` on what is now a `str`
     (`ms_data.rst:208`, `spectrum_alignment.rst:53`).
   - `Residue.getMonoWeight()` lost its default argument (`peptides_proteins.rst:78`).
   - `MSDataCachedConsumer(filename)` lost its default argument (`reading_raw_ms_data.rst:250`).
   - The deprecated `get_df(long=True)` alias no longer accepts `long`
     (`export_pandas_dataframe.rst:66`).

   The rest are intentional API changes that the CHANGELOG does not announce as breaking and
   the user guide does not follow (table under D5).
2. **D1 — removed Python API is not announced.** 36 public names are gone since 3.5.0, and 25
   of them appear nowhere in the 3.6.0 CHANGELOG. They include `DPosition1`/`DPosition2`
   (still used in `ms_data.rst:801`), `IsotopePattern`, `OSWFile`, `ProteinInference` and
   `PeptideSearchEngineFIAlgorithm` (list under D1). The chemistry databases changed from
   classes to callable singletons.
3. **F6 — the DEB and the macOS package bundle OpenSSL 3.0.8.** `/usr/lib/libcrypto.so.3` in both DEBs and `libcrypto.3.dylib` in the `.pkg` are affected by
   CVE-2025-15467 (High, fixed in 3.0.19) and CVE-2026-45447 (High, fixed in 3.0.21), plus 9
   Moderate and 40 Low advisories (per [openssl-library.org](https://openssl-library.org/news/vulnerabilities-3.0/)).
   The pin is `"overrides": [{"name": "openssl", "version": "3.0.8"}]` in OpenMS `vcpkg.json`.
   The Linux wheel bundles OpenSSL 3.5.8, which is not affected.
4. **A2 — the newest wheels and installers come from different commits.** The 2026-09-24 wheel
   build failed ([run 35943339116](https://github.com/OpenMS/OpenMS/actions/runs/35943339116):
   the Linux ARM job stopped at configure with `CMAKE_CXX_COMPILER not set` and
   `ninja: command not found`), so no wheel exists for `79d6d8a`. The 7 commits between the
   two revisions do not touch `src/pyOpenMS` or `doc/pyopenms`, so the pyOpenMS findings hold
   for both.
5. **E4 — headline features lack user documentation.** Nothing documents transparent
   `.gz`/`.bz2`/`.zip` input. The ProteomicsLFQ page does not mention PIP-ECHO
   match-between-runs. Imaging (imzML) has class docs only. There is no C++ migration guide
   for the `OpenMS::String` removal. The pyOpenMS user guide mentions only 5 of the 140 new
   Python classes, and none of the headline ones (ProForma, USI, MzPAF, `ThermoRawFile`,
   `BrukerTimsFile`, imaging, Parquet/Arrow IO, PEFF, glycans).
6. **E1, E2, E8 — CHANGELOG and tool pages.**
   - The new tools ParquetConverter and ParquetDiff are missing from *New tools*.
   - The removal of QuantmsIOConverter (the 3.5.0 name) is announced as "QPXConverter
     removed".
   - SwathWizard and FLASHDeconvWizard are gone without a CHANGELOG entry.
   - The new TransitionListEvidenceFilter page does not show its parameters.
   - The CHANGELOG has a duplicated bullet with conflicting numbers and two orphaned sentence
     fragments.
7. **F1, C6 — the release claims more platforms than the packages support.**
   - The CHANGELOG says macOS 14; the wheels are tagged `macosx_15_0`
     (`MACOSX_DEPLOYMENT_TARGET = "15.0"` in `pyproject.toml`).
   - The Linux install page offers the DEB for "Debian and Ubuntu" without versions, but it
     needs glibc 2.38 (Ubuntu 24.04 or Debian 13).
8. **C5 — the vendor readers work only on the non-default path.**
   - `FileConverter -in x.raw` fails on a stock Linux installation: the default reader is still
     the external ThermoRawFileParser (`ThermoRawFileParser.exe` not found, exit 14). The new
     native reader works, but only with `-RawToMzML:reader inprocess`.
   - Bruker `.d.zip` input, which the CHANGELOG advertises, fails in FileConverter and in
     pyOpenMS `BrukerTimsFile`. Unzipped `.d` directories read correctly.

9. **C3 — on macOS, `ExecutePipeline` cannot start, so TOPPAS pipelines cannot run from the
   command line.** All seven TOPPAS tests fail at start-up with
   `qt.qpa.plugin: Could not find the Qt platform plugin "cocoa" in ""`
   ([run 35977643534](https://github.com/timosachsenberg/openms-test-lab/actions/runs/35977643534)). Every other upstream test passes there.
   - The package ships `lib/plugins/platforms/libqcocoa.dylib`, but only the app bundles are
     told where it is: each `.app` gets its own `qt.conf` (`src/openms_gui/add_mac_bundle.cmake`).
   - `bin/` has no `qt.conf`. Its install is commented out in
     `cmake/package_mac_productbuild.cmake:86-95` ("Not needed unless we need Qt plugins for
     TOPP again"), and the TOPP Shell profile sets no `QT_PLUGIN_PATH`.
   - `ExecutePipeline` is a GUI TOPP tool (`GUI_TOPP_TOOLS` in `src/openms_gui/CMakeLists.txt`)
     and opens a Qt application, so it needs the plugin.
   - Installing `bin/qt.conf` with `Plugins = ../lib/plugins` should fix it (not verified). The
     Windows installer installs its `bin/qt.conf` and passes all seven tests.

Release mechanics (G) were not exercised, because that needs a release-candidate tag. Reading
the code shows that a `v3.6.0` tag build would report its version as `3.6.0-pre-HEAD-<date>`
(see G2).
