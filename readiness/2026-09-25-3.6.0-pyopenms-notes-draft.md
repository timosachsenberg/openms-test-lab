# pyOpenMS 3.6.0: draft BREAKING notes (2026-09-25)

**Status: draft for the maintainers.** Nothing here is in the OpenMS CHANGELOG yet. It answers
D1 and D5 of the [2026-09-25 readiness report](2026-09-25-3.6.0-nightly.md). Along the way it
found binding bugs in the 3.6.0 nightly that should be fixed rather than announced (section 2).

**Method.** pyopenms 3.5.0 from PyPI was compared with 3.6.0.dev20260925, the nightly wheel
built from OpenMS `8b25c6e`. Both ran on CPython 3.11. The method signatures of every class were
parsed from the docstrings of both builds (autowrap in 3.5.0, nanobind in 3.6.0). A 3.5.0 call
form counts as changed when no 3.6.0 overload accepts it. The full mechanical list is in
[2026-09-25-3.6.0-pyopenms-call-forms.md](2026-09-25-3.6.0-pyopenms-call-forms.md). Every example
below was run in both versions and gives the same result there. The pending `feature_id`
decision in OpenMS/OpenMS#10260 is left out.

## 1. Proposed CHANGELOG entries (PyOpenMS section)

The existing entry for #8699 says the port "fixed mutable-reference output parameters and
restored missing default arguments". The first half becomes the first BREAKING entry below.
The second half is not true yet (bug B4), so it should go.

```
  - BREAKING: output arguments are return values. A method that filled a list or object
    passed by the caller now returns it; the old call raises TypeError. For example:
      picked = oms.PeakPickerHiRes().pickExperiment(exp)   # was pickExperiment(exp, picked, True)
      traces = oms.MassTraceDetection().run(exp)           # was run(exp, traces, 0)
      trafo = aligner.align(feature_map)                   # was align(feature_map, trafo)
      decomps = decomposer.getDecompositions(262.1)        # was getDecompositions(decomps, 262.1)
      proteins, peptides = oms.ProtXMLFile().load(path)    # was load(path, proteins, peptides)
      ok, errors, warnings = oms.MzMLFile().isSemanticallyValid(path)
      names = oms.RNaseDB().getAllNames()                  # was getAllNames(names)
    The same holds for FileHandler.loadFeatures and the load() of MzTabFile, SqMassFile,
    DTAFile, DTA2DFile, EDTAFile, KroenikFile, ChromeleonFile and MRMFeatureQCFile, among
    108 call forms in all (list: <link>). MzMLFile, FeatureXMLFile, ConsensusXMLFile and
    FileHandler.loadExperiment still fill their argument, and IdXMLFile.load accepts both
    forms (#8699).
  - BREAKING: strings inside returned containers are str instead of bytes: list and set
    elements, dict keys (EmpiricalFormula("H2O").getElementalComposition() is now
    {'H': 2, 'O': 1}), Param keys and tags, list-valued string meta values and string data
    arrays, as well as the few methods that returned bytes (172 methods, list: <link>).
    Methods returning a single String already returned str. Drop .decode() calls and b"..."
    keys and comparisons.
  - BREAKING: LogConfigHandler has no constructor any more. Use
    oms.LogConfigHandler.getInstance().setLogLevel("ERROR") instead of
    oms.LogConfigHandler().setLogLevel("ERROR").
  - BREAKING: CrossLinksDB, ElementDB, ModificationsDB, ProteaseDB, ResidueDB,
    RibonucleotideDB and RNaseDB are callable singletons. ModificationsDB() and
    ModificationsDB.getInstance() return the one shared instance, but the names are no longer
    classes: isinstance(x, oms.ModificationsDB) is False.
  - BREAKING: <removed classes: see section 3>
  - BREAKING: nested enums were renamed where autowrap had prefixed them: IonDetector.Type
    (was Type_IonDetector), FeatureDeconvolution.CHARGEMODE and
    MetaboliteFeatureDeconvolution.CHARGEMODE (were CHARGEMODE_FD / CHARGEMODE_MFD),
    OpenPepXLAlgorithm.ExitCodes, PeptideIndexing.ExitCodes and PercolatorOutfile.ScoreType
    (were prefixed with the class name). The enums' getMapping() helper is gone. Seventeen
    enums, mostly metadata ones such as IonSource.IonizationMethod, SpectrumSettings.SpectrumType,
    Precursor.ActivationMethod and the MassAnalyzer enums, no longer convert with int(): use
    .value. Setters such as IonSource.setIonizationMethod() still accept an int (#8405, #8604).
  - The typing helpers List and Union and the streampos class are no longer exported.
```

`<link>` stands for wherever the call-form list ends up, for example a migration page in the
pyOpenMS documentation. For now it is
[2026-09-25-3.6.0-pyopenms-call-forms.md](2026-09-25-3.6.0-pyopenms-call-forms.md).

After bug B2 is fixed, add:

```
  - BREAKING: copy constructors X(other) were removed from 143 classes; use copy.copy(x) or
    copy.deepcopy(x).
```

## 2. Bugs in the 3.6.0 bindings (for OpenMS/OpenMS#10260, not for the CHANGELOG)

B1 to B3 were run against the nightly. B4 and B5 come from the signature comparison and the C++
headers. File references are to `develop` at `0d8d3bbb`.

**B1. `SimpleSearchEngineAlgorithm.search()` always fails.** The search runs to the end and
prints its statistics. Then the call raises `RuntimeError: std::bad_cast`. The binding returns
`nb::make_tuple(result, prot_ids)`, where `result` is `SimpleSearchEngineAlgorithm::ExitCodes`,
an enum no binding registers (`src/pyOpenMS/bindings/bind_misc.cpp:3659-3664`). The ExitCodes of
PeptideIndexing, ProSEAlgorithm and OpenPepXLAlgorithm are registered.
Fix: register the enum, or return `static_cast<int>(result)`. The `peptide_search` page of the
user guide depends on this call.

**B2. `copy.copy()` and `copy.deepcopy()` return the wrong class.** In 3.5.0 they return an
object of the same class. In 3.6.0, 52 classes come back as their bound base class. For example,
`copy.copy(oms.PeakPickerHiRes())` is a `DefaultParamHandler` without `pickExperiment`, and
`copy.copy(oms.GaussFilter())` is a `ProgressLogger`. The affected classes derive from
DefaultParamHandler, ProgressLogger, CVTermList, CVTermListInterface or CsvFile. Only the base classes define
`__copy__`, so every derived class inherits a copy that slices. Eight classes cannot be copied at
all: DataFilter, DataFilters, EmgScoring, ExperimentalDesign_SampleSection, IDFilter,
ILPDCWrapper, MassTraces and SeedListGenerator. The copy constructor `X(other)` is gone from all
143 classes in appendix C, so these objects cannot be copied correctly by any route.

**B3. In/out arguments were bound as pure outputs, so the input cannot be passed.** Each of these
has a non-const reference parameter that C++ reads.
- `TheoreticalSpectrumGeneratorXLMS.getLinearIonSpectrum(link_pos, frag_alpha, charge, link_pos_2)`
  returns `(MSSpectrum, AASequence)`. It has nowhere to take the peptide, so it always generates
  from an empty sequence: 0 peaks, and the warning "Attempt at creating XLink Ions Spectrum from
  empty string!". `getXLinkIonSpectrum` has the same problem, and SimpleTSGXLMS repeats both. The
  C++ peptide or crosslink arguments are `AASequence&` / `ProteinProteinCrossLink&` inputs
  (`CHEMISTRY/TheoreticalSpectrumGeneratorXLMS.h:82,107`, `CHEMISTRY/SimpleTSGXLMS.h:106,130,149`).
- `OPXLHelper.computeDeltaScores()` takes no argument and returns an empty list. C++ scores the
  identifications it is given in place (`ANALYSIS/XLMS/OPXLHelper.h:210,213`).
- `IsotopeLabelingMDVs.calculateMDVAccuracy(feature_name, formula)` throws "Missing values for the
  Measured Isotopomer Fragment". C++ reads the subordinates of the feature it is passed
  (`IsotopeLabelingMDVs.cpp:200-212`), which the binding can no longer take.
  `calculateIsotopicPurity` only writes to its feature, so it still works, but it returns a new
  Feature instead of annotating yours.

**B4. C++ default arguments are missing from 27 call forms** (appendix B). This is the same kind
of problem as the known `Residue.getMonoWeight()` and `MSDataCachedConsumer(filename)` regressions.
Others users will hit:
- `Residue.getAverageWeight()` and `Residue.getFormula()`;
- `MetaInfo.getValue(name)`, which now requires a default value;
- `FineIsotopePatternGenerator(threshold)`;
- `ModificationDefinition(mod, fixed)`;
- `IDFilter.removeDuplicatePeptideHits(peptides)`;
- `IDConflictResolverAlgorithm.resolve(features)`;
- `TextFile(filename, trim_lines, first_n)`;
- `MzMLSpectrumDecoder()`;
- `JavaInfo.canRun(java)`.

**B5. Overloads that were dropped or became inconsistent** (appendix E lists 167 call forms to
review). Some of these are plainly unintended:
- `replaceCVTerms(cv_terms, accession)` is gone from CVTermList, CVTermListInterface and the
  classes derived from them (17 call forms); only the map overload remains;
- `ConsensusIDAlgorithm*.apply(ids, number_of_runs)` now requires `se_info`, although C++ still
  has that overload (`ANALYSIS/ID/ConsensusIDAlgorithm.h:49`);
- `MapAlignmentAlgorithmIdentification.align(maps, trafos, reference_index)` is gone. The binding
  only wraps a single map in a one-element vector (`bind_misc.cpp:3032-3040`), so several runs can
  no longer be aligned together to a consensus of all runs. C++ still offers that
  (`ANALYSIS/MAPMATCHING/MapAlignmentAlgorithmIdentification.h:93`);
- `FileHandler.loadFeatures(path, map)` is gone, while `loadExperiment(path, exp)` stays;
- `RNaseDB.getAllNames(names)` is gone, while `ProteaseDB.getAllNames(names)` stays;
- `ModificationDefinitionsSet.getModificationNames(fixed, variable)` is gone, although C++ still
  has it (`CHEMISTRY/ModificationDefinitionsSet.h:101`).

The readiness report already lists four known bugs: the `.decode()` in `pyopenms.plotting`,
`get_df(long=True)`, `MSDataCachedConsumer(filename)` and `PeptideEvidence.setAABefore(b"A")`.

## 3. Removed classes (D1)

Pending. For each of the 22 classes, it is still being checked whether the C++ class went too,
whether the binding was dropped on purpose, and what replaces it in 3.6.0. The last BREAKING
entry in section 1 is filled in from that.

## 4. Not covered

- Appendix E: which of the 167 changed call forms are intentional. It needs one pass by someone
  who knows the port. An intentional one needs a note; the rest are B5 bugs.
- Enums, partly. R's `pyopenms-api-diff.json` lists 401 `members_removed_from_every_class`. Of
  the 259 that are enum values, 195 still resolve under their 3.5.0 spelling, such as
  `IonSource.IonizationMethod.APCI`: that part of the list is an artefact of how the snapshot
  walks classes. The enum entry above covers the rest, except for three enums with no
  replacement: `SignalToNoiseEstimatorMeanIterative.IntensityThresholdCalculation`,
  `SignalToNoiseEstimatorMedianChrom.IntensityThresholdCalculation` and
  `XFDRAlgorithm.MassIntensityType`. Also gone is `PeptideIndexing.ExitCodes.DECOYSTRING_EMPTY`.
  Whether those are intentional needs checking. The other 142 names are not enum values and were
  not looked at.
